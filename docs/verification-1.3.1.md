# 1.3.1 验证记录

2026-10-22。实现用户在Haru接入期间追加的三项需求。全部测试使用临时数据目录，没有安装覆盖用户软件或修改正式工资账本。

## 功能
- 无声休息提醒：5–240分钟，每个工作时段从上班起点重新计时，默认关闭。跨午休、下班、非工作日、隐藏状态和过期提醒均不弹出；去重持久化。
- 默认显示名“丝袜妹”，可保存1–20字名称，设置/预览/桌面/概览/成长一致；Haru模型版权署名保留。
- 日历卡片显示已结算、今日当前或未来全天预计金额。入职前不计薪；2026年13个法定节假日按正常日预算带薪，普通休息与调休不误算。分母仍是正常周排班天数。旧账本不自动改写；需要调整过去收入时，由用户主动重算。

## 验证
- 109项单元测试通过；新功能用例先失败后修复。类型检查和构建通过。
- 新设置名称/提醒间隔保存与重启、国庆与普通休息金额、未来预算、无声休息气泡，两项真实Electron测试通过。日历截图人工查看，金额无重叠或裁切。
- 完整Electron回归首次31/34通过。发现并修复异步保存断言过早、最终一次模型加载等待过短，以及真实WebGL上下文丢失先于事件通知的竞态。最终打包版9/9关键回归通过：包括三项之前失败的用例、全部追加功能、14个表情/动作预览与持久化、v1/v2升级。20次切换无活动上下文或RAF残留，断网静音验证通过。正常持续显示一分钟的用例在完整回归中通过。
- 独立审查发现同源但部分日期的旧日历补充付薪元数据会造成启动校验失败，已以失败用例修复：仅补充保存日历中days=false的日期。
- 将“延迟提醒跨到午休”的小项按明确需求视为应修复：新增失败用例并限制当前时刻仍在原工作时段。通过测试，不保留该缺陷。

## 实施裁定与限制
沿用用户已授权的直接实现方式，追加需求按现有流程做有界改动。名称和提醒均为向后兼容默认字段，不覆盖历史金额。手动设为休息仍优先于带薪节假日，需要恢复自动判断才重新应用官方标记。日历完整年度元数据缺失时不猜农历假日。

Haru部分的完整裁定见 verification-1.3.0.md：SDK下载与迁移并行；完整SDK含音频但应用不导入；官网维护期间使用官方索引核对许可；真实入口代替产品专用测试路由；Framework独立编译并维护着色器生命周期小补丁；帧率问题提升为重要并修复。成本分别是任务顺序、公开发布前许可复核、跨任务共同验证、SDK升级时重验补丁和独立帧调度状态。

暂缓小项仍只有：事件出现后4秒内切回角色可能重播一次动作，但不会重复成长奖励。未人工验证跨物理DPI显示器、系统睡眠及安装向导全过程；这些不由自动化冒充。未公开发布。
