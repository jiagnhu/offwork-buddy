# Haru Live2D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有下班搭子中增加可以真实预览、原地自然陪伴、无声互动的 Haru Live2D 角色，并保留用户的工资与成长数据。

**Architecture:** 通过官方 Cubism Web Framework + Core 封装独立 HaruRuntime，React 管理画布与可见性。资源由只读白名单本地协议提供；角色能力表统一控制窗口大小、散步和配饰。状态升级到 v3，旧版本先备份再迁移。

**Tech Stack:** Electron 45、React 19、TypeScript、Vite、Zod、Vitest、Playwright Electron；官方 Cubism Web Framework/Core/Haru 资源的具体兼容版本在 Task 1 校验后锁定，禁止跟随浮动 develop。

**Spec:** `docs/superpowers/specs/2026-10-22-haru-live2d-design.md`

## Global Constraints

- 升级不自动替换当前角色。
- 当前模型暂无行走动作。Haru 不自主位移；切换回原角色不丢失散步偏好。
- 保持无声，不添加语音、口型同步、摄像头、麦克风或 AI 聊天。
- 目标每秒 30 帧；只有可见且正在使用的画布渲染。
- 减少动画时关闭循环待机、物理和指针追踪，保留静态表情反馈与气泡。
- 运行资源本地提供，不依赖 CDN 或启动时联网，不关闭 webSecurity/contextIsolation/sandbox。
- 已有金额、规则、计划、奖励和坐标原样保留，不重算历史金额。
- 现有 SVG 星星/抱枕不直接贴到 Haru 上；数据保留，界面说明适用角色。
- 默认基准尺寸 360×500；如动作画幅确需调整，仅调整能力表中的尺寸并同步验证，记录理由。
- 使用当前 checkout，保留并行官网工作的变更；测试仅使用 BUDDY_DATA_DIR 临时目录，不安装覆盖正式用户程序。

## Review Focus

1. 隐藏窗口的异步加载稍后完成：不得启动不可见的动画循环（Task 3 生命周期测试）。
2. 切换 Haru/旧角色时同一次点击的反馈晚到：不得作用于已卸载的模型或重复奖励（Tasks 3、5）。
3. 缺资源、错误 MIME、ASAR 打包路径与恶意协议 URL：不能白屏拖垮主界面，也不能访问白名单外文件（Tasks 2、6）。
4. 原备份中的旧 schema 与未知未来 schema：旧数据迁移前保存原文；未知版本拒绝，不当作首次启动清空（Task 4）。
5. Haru 已加载时 GPU 上下文丢失、减少动画切换与隐藏恢复：停止旧循环、提供恢复入口，不能累积画布/纹理（Tasks 3、6）。

## 文件边界与依赖

- `resources/live2d/`：官方 Core、Haru 文件与资源锁定清单；`vendor/cubism-framework/`：固定版本官方 Framework 源码与许可证。
- `scripts/prepare-live2d.mjs`：开发期获取/校验官方资源；`scripts/verify-live2d.mjs`：纯本地清单、哈希、引用和静音检查。构建不能自动下载。
- `src/main/live2d-assets.ts`：本地协议注册与白名单响应；`src/shared/character-capabilities.ts`：尺寸和功能支持。
- `src/renderer/characters/live2d/`：Core 加载、模型/纹理资源、动画运行时、事件映射、React 画布组件，各自职责分离。
- `src/renderer/components/HaruPreview.tsx`：预览弹窗和动作试用；Settings、Growth、Character、Companion 只负责选择与调用。
- 状态迁移在 shared migration/schema 与 main store/backup 中实现，不通过渲染器修改历史金额。
- 依赖顺序：Task 1 → 2 → 3；Task 4 独立于渲染实现；Task 5 消费 3/4；Task 6 完整验收与交付。
