# 下一版：安静的桌面伙伴

## 目标与已确认需求

在现有 Electron Windows 应用上增加无声提醒、桌面今日计划、工资计算明细、角色互动成长与屏幕底部散步。用户明确选择「屏幕底部散步为主」，所有提醒均无声音。延续现有中文界面、原创建模角色、本地保存、大小周排班和计薪口径。

成功标准：角色有自主动作但方便控制；数字和待办位置稳定；每笔收入能解释；完成计划有轻量反馈；旧数据可迁移；双屏拖动、睡眠唤醒和隐藏恢复不丢失窗口。

以下时长、奖励数值和解锁内容为本设计提出的默认值，可在实现前调整。

## 交互设计

### 1. 屏幕底部散步

- 两种模式：底部散步（默认）、原地陪伴。两种角色均可使用；不增加全屏探索模式。
- 散步限定在当前显示器的工作区底部，脚底距可用区域下沿约 12 DIP，避开任务栏。角色完整留在屏内，双屏不会自主跨屏。
- 每次步行约 4–8 秒、移动约 80–160 DIP，随后停留 20–45 秒；到达边缘转身。行走有朝向、踏步动作，停留可坐下、伸懒腰或打盹。
- 鼠标进入角色窗口外扩 60 DIP 的区域时停止；离开 2 秒后才能继续。固定看板所在矩形也属于避让区域；底部没有足够连续空位时保持原地，不强行穿过看板。
- 用户拖动优先，拖动期间停止自主移动。松开后在放置位置停留 60 秒，然后缓慢沿安全路径回到底部活动区；手动拖到另一屏后，以该屏为新的活动屏幕。拖动不改变固定看板位置。
- 角色工具条提供「暂停散步 / 继续散步」「叫回伙伴」「隐藏伙伴」及原有切换角色、设置入口。叫回后回到看板附近的可见位置，停留 60 秒；空间不足时选最近可见位置。
- 开启「减少动画」时禁用自主移动与循环动画，点击反馈、提醒和成长仍可用。隐藏、系统休眠时停止行为计时；唤醒重新校验屏幕范围并从短暂停留开始，不补执行离线动作。
- 显示器拔除后迁回主屏工作区；分辨率、缩放改变时重新约束边界。明确隐藏的伙伴不会因提醒、显示器变更或休眠恢复自动出现。

### 2. 固定信息卡与今日计划

- 角色窗口与信息卡窗口独立，卡片保持用户拖放位置，不跟随散步。默认置于现有窗口附近并约束在屏幕内。
- 保留今日预计收入和单一阶段倒计时，不恢复累计金额或英文装饰标签。
- 卡片增加下一项未完成的今日计划与复选框；显示「已完成 / 总数」，展开后可以查看、勾选或取消今天全部计划。
- 空状态提供「添加今日计划」，打开主面板日历并选中今天；全部完成时显示「今天的计划已完成」。新增、修改与删除仍由现有日历承担。
- 主面板与卡片操作同步；按计划 ID 提交完成状态变更，主进程基于最新数据处理，避免两个窗口同时操作覆盖整日列表。失败时保持原状态并显示可重试提示。
- 卡片可单独收起或隐藏；隐藏整个桌面伙伴会同时隐藏卡片和角色。「桌面模式」显示角色，并按卡片收起设置恢复卡片。

### 3. 无声提醒

- 默认提醒：午休前 5 分钟、午休开始、下班前 5 分钟、下班到点。未设置午休时只产生下班提醒。
- 设置中可分别开关午休提醒、下班提醒；提前量可选 0、5、10 分钟，0 表示仅到点提醒。
- 使用应用内气泡和卡片提示，不调用系统通知，不使用音频、提示音或语音。角色可短暂伸懒腰或挥手；减少动画时只显示文字。
- 每次显示约 8 秒，可手动关闭；不抢键盘焦点。临近提醒时暂缓走动。时间提醒优先于普通闲聊，计划完成反馈延后，不互相覆盖。
- 仅在累计开始日期之后、已配置的实际工作日产生提醒，遵循当天生效的作息和手动日历覆盖。
- 初次启动不追补已经过去的提醒；运行中跨越触发点且延迟不超过 60 秒时允许提醒。休眠恢复后跳过超过 60 秒的过期提醒，避免通知堆积。
- 主进程作为唯一提醒源，保存「日期 + 事件类型 + 当天目标时间」去重标记，保留最近 30 天。设置切换不重复触发同一事件。两个桌面窗口共享一个事件，不各自计时触发。
- 桌面伙伴整体隐藏时不弹窗；记录该事件已跳过。以后显示不补发。

### 4. 工资计算明细

- 点击主面板收入卡、桌面今日金额或账本单日记录可查看明细。桌面入口打开主面板相应明细，不挤占角色窗口。
- 今日明细展示：计薪方式、当日生效金额、正常排班分母（按月模式）、每日预算、工作时段、午休时段、有效总工时、已计工时、今日累计和分舍入说明。
- 月薪示例：16,000 ÷ 24 天 = 666.666… 元预算；今日金额使用未提前舍入的预算乘工时比例，最终四舍五入到分。完整三日逐日结算为 2,000.01 元，明确显示此舍入方式。
- 日薪、时薪显示各自公式，不展示无关的月分母。休息日说明是哪一层规则判定为休息；未入职或未配置说明尚未开始计薪。
- 累计明细拆成「已结算历史合计 + 今日实时收入」，按日期列出，展示累计起始日期。
- 历史明细以保存的规则、排班快照、分母、金额为准，不用最新日历反推旧金额。新增账本记录保存明确的算法标记；旧记录缺少标记时标为「历史结算」，如果保存分母与该规则的正常排班分母不同，则显示差异与重算入口。不能可靠判定的旧记录不猜测算法版本。
- 明细入口不自动重算历史；继续使用现有选择区间、明确确认的重算流程。工资算法本身不变，带薪假、真实考勤、税费、加班费仍不新增。

### 5. 角色互动与成长

- 首版使用现有分层 SVG，新增清晰可辨的走路、坐下休息、伸懒腰、挥手庆祝动作。看板娘和猫咪使用各自适合的姿态，提供少量本地中文气泡。
- 点击角色产生回应，完成今日计划播放短暂庆祝；重复点击有冷却，避免气泡和动作不断覆盖。
- 两种角色共用陪伴成长，切换角色不清零。首次每日互动 +1 陪伴值；当天计划首次完成每项 +2，每天最多奖励 5 项。每天最多获得 11 点，无签到连续天数要求，不因离线或未完成而扣分。
- 奖励只针对升级后完成的当天计划；历史计划、未来计划以及旧备份迁入的已完成项目不补奖励。取消后重新完成同一计划不再奖励，删除重建也受每日奖励数量上限约束。
- 解锁阈值：0 点基础动作；10 点星星配饰；30 点抱枕与抱枕休息姿态；60 点额外庆祝动作。配饰均可关闭，不影响计薪和计划功能。
- 成长页展示当前陪伴值、解锁物品、下一项解锁进度；不增加货币、抽奖、商城或工资挂钩奖励。

## 架构与数据

### 窗口职责

现有主面板保持不变；桌面拆成紧凑角色窗口与固定卡片窗口。复用统一快照与现有受限 IPC、contextIsolation 和 sandbox。避免创建覆盖整个屏幕的大透明窗口。

主进程管理显示、隐藏、置顶、位置和活动屏幕；角色 React 页面负责 SVG 姿态和气泡，卡片页面负责计时与计划。所有显示入口统一恢复两个窗口的合法位置，遵循各自收起状态。

### 行为控制

新增独立行为控制器：idle、walking、resting、reacting、dragging、paused。接受可注入的时钟、随机源、屏幕工作区和鼠标位置，便于确定性测试。

主进程负责路径和目标坐标；行走期间最多 30 次/秒更新位置，静止时只低频检查接近与行为期限。只有坐标确实变化才调用 setPosition。自主动画坐标不触发逐帧持久化、不调用保存偏好的完整链路；仅手动拖动结束、模式改变或正常退出时保存稳定位置。

优先级：隐藏/休眠 > 用户拖动或暂停 > 鼠标接近 > 提醒/互动 > 自主活动。最近的双屏问题不能仅凭模拟测试宣布解决，真实双屏拖动仍是交付验收项。

### 模块划分

- reminder：纯函数判断提醒窗口与去重，主进程负责事件分发和持久化。
- companion-behavior：动作状态、停留期限、路径边界、鼠标避让。
- earnings-explanation：与实际 calculateDay 共用计算结果或计算分解，杜绝独立复制公式产生不同数字。
- growth：原子应用奖励与解锁，验证去重和每日上限。
- desktop-card：固定倒计时、今日金额和按 ID 更新的今日计划。

### 数据兼容与失败恢复

新增提醒偏好、移动模式、卡片位置、角色稳定位置与屏幕信息、成长值及奖励去重标记、提醒去重标记。使用明确的新 schema 版本与单向迁移，旧 1.x 备份可读取；迁移前保留原始副本，失败不覆盖原文件。

旧计划、工资规则、历史金额、主题、角色、缩放与置顶完整保留。现有 position 用作迁移时的锚点，卡片和角色位置分别约束到有效显示器。已有减少动画设置优先，迁移后不会擅自启用走动。

计划完成与成长奖励放在同一次串行保存中，只有保存成功才广播完成与奖励反馈；重复请求保持幂等。运行时散步不依赖高频磁盘写入。提醒标记保存失败时，本次运行保留内存去重并显示持久化错误，避免反复提醒。

## 实现顺序与验收

1. 数据迁移、计薪明细和主面板入口。
2. 角色与卡片拆分、桌面计划同步、统一显示找回。
3. 无声提醒与事件优先级。
4. 底部散步、手动接管、鼠标避让及多屏恢复。
5. SVG 姿态、成长去重与配饰解锁；整体验证和 Windows 安装包。

必须验证：旧数据往返备份；明细与实际金额逐分一致；旧新账本混合解释；双窗口同时修改不同待办；重复完成不刷奖励；提醒跨分钟、跨日、重启和睡眠不重复；无音频和焦点抢占；负坐标、多 DPI、任务栏和显示器拔除；隐藏后不自动冒出；减少动画禁用走动；坐标更新不写磁盘；安装后工资记录保持不变。

单元测试覆盖纯计算与边界，Electron 测试覆盖窗口、IPC 与持久化，截图覆盖两角色、固定卡片、明细与成长页面。物理双屏拖动和睡眠恢复单独记录是否实际验收，不用程序化移动替代完整人工验证。

## 本版边界

不读取其他软件内容，不识别桌面图标和窗口边缘，不爬窗口，不自动跨屏，不访问网络生成对话；不引入 Live2D、外部模型或付费资源。自由全屏探索与更多角色资源留待后续需求。
