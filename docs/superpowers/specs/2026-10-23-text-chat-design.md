# 首版文字聊天设计

日期：2026-10-23
状态：接入方案已确认；以下产品细节为实现建议，待确认。

## 目标与范围

在现有 Electron 桌面伙伴中加入无需登录的文字聊天。用户已选择百炼千问，由产品统一管理模型，用户不能设置 API Key、接口地址或模型。暂不加入账号、支付、语音、联网搜索、自动操作工作计划与工资数据。

## 方案选择

已讨论百炼千问、DeepSeek 官方接口与 Kimi。选择百炼千问，便于后续接入语音；服务端保留供应商适配边界，不暴露给最终用户。默认非思考、流式输出。具体可用模型标识和地域在接入时根据开发者的百炼服务核实，配置在服务端，不凭空填写。

## 交互建议

- 主面板新增“伙伴聊天”菜单；桌面角色头顶菜单增加聊天按钮，打开主面板并进入聊天页。首版复用主窗口，不创建新的悬浮聊天窗口，避免影响拖动与显存。
- 聊天页使用当前角色的静态头像、名称、消息列表、输入框；不额外加载 Live2D。普通点击角色仍触发原有互动。
- 每个角色独立一份会话；切换当前角色后显示对应历史。提供不同的简短默认人设，首版不做复杂人设编辑器。猫角色以拟人化语气聊天。
- 输入限制 2000 字；Enter 发送、Shift+Enter 换行，中文输入法组合输入期间不发送。
- 流式显示回复；支持停止、失败重试、清空当前角色历史（确认后执行）。不强制用户跟随滚动，用户向上阅读时显示回到底部入口。
- 整个应用同时只允许一个生成请求。切换菜单时继续生成；切换角色时停止旧请求并保留已输出的内容。停止后保留部分回复并标记中止，不当作完整回复带入下次上下文。
- 错误提示区分未配置服务、超时、网络异常、上游限流等，避免将原始异常或密钥显示给用户。重试不重复添加用户消息。

## 数据与请求

- 独立 chat.json 保存每个角色的记录，由 Electron 主进程负责原子写入与串行修改，不修改工资文件格式。历史保留最近 500 条/角色，界面告知这一上限；发送时仅携带最近 20 条已完成消息并实施总长度上限。
- 消息含 id、role、内容、时间与状态；生成片段批量刷新界面，完成/停止后落盘。异常退出后未完成记录标记中止。
- 通过受控 IPC 发送、停止、读取、清空；主进程负责请求 ID、会话归属、取消与去重，防止迟到片段写入另一角色。
- 仅将当前聊天上下文与角色设定发送到服务端，不自动上传工资、请假、计划等资料。聊天页首次使用显示这一说明。

## 服务端与开发边界

- 新增独立 Node.js/TypeScript 聊天服务，以环境变量配置百炼密钥、地域端点和模型。密钥不进入渲染进程、安装包、代码仓库或日志。
- Electron 调用产品聊天服务，服务端调用百炼并转发流式结果；限制消息大小、并发、超时，并在用户取消时取消上游请求。
- 无账号阶段只在本机运行开发服务（监听回环地址），不部署匿名公网付费接口。未来发布收费服务前再加入服务认证、额度与防滥用机制。
- 开发者通过本地环境变量设置服务与百炼凭据；最终用户界面没有模型设置。缺少凭据时明确提示服务尚未就绪，不使用假回复冒充真实 AI。
- 测试通过本地模拟流验证功能；真实连通验证需要开发者提供已开通的百炼配置，密钥在本地录入，不要求贴到聊天。

## 验收

1. 可从主面板和桌面角色菜单进入聊天，不改变原有单击互动。
2. 角色历史独立，重启恢复；流式回复、停止、失败重试及清空可用。
3. 快速切页、切角色、停止后重发均不会串消息或重复写入。
4. 模型/密钥配置仅服务端可见；无凭据有真实错误提示。
5. 回归页面切换、共享模型、拖动与工资功能；测试对超时、取消、断流、损坏历史文件有覆盖。
6. 真实接口与模拟接口的验证结果分别报告；未连通真实接口时不宣称真实聊天已验证。

## 留给实现者

沿用现有 React、Electron IPC、TypeScript 和测试体系；确定文件拆分、流事件格式、批量刷新频率及默认角色文案。视觉沿用现有明暗主题和圆角卡片，不重新设计整套应用。
